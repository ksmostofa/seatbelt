Every item is pending. This is a preparation plan, not a progress report.

## Priority 1: real factory and complete contract

Prepare the organizer kickoff package in a separate directory, verify prerequisites and configure the BAND seats with generic mandates. Rehearse on the unscored toy track. Correct factory setup before the scored run.

Ask the genuine BAND factory to implement Tablekeeper stages in order. Give it the complete official specification rather than a summary. Each stage needs a complete buildable service and cumulative compatibility with earlier requirements. Independent verification must cover omitted specification cases, not just shipped checks.

## Priority 2: customer experience

Use shadcn preset `b1VlJBjs` and RareUI components only. Follow the official stage-2 browser contract, including selector and accessibility requirements, without letting component defaults change required behavior. Provide responsive search, availability, booking, confirmation and lookup/cancellation screens with loading, empty, error and recovery states.

The UI must call the real service. Do not substitute simulated confirmations or pretend a failed request succeeded. Preserve a request's identity across retry as the specification requires.

## Priority 3: differentiated manager interface

After required behavior works, add views over the prescribed advanced operations:

- Effective-dated policy history and accepted booking terms.
- Recurring agreements with independently identifiable occurrences and exceptions.
- Closure recovery preview with affected reservations, planned seating and clear differences.
- Atomic apply with conflict or failure reporting and a refreshed current state.
- Original confirmation versus current seating, so historical receipts remain truthful.

These additions must not alter the required API, introduce unauthorized state changes, or break earlier stages. Skip optional polish if it threatens completion or authentic evidence.

## Priority 4: reproducible evidence and demo

Run each completed folder in isolated mode through the organizer harness. Preserve independent checks and exact accepted commits. Complete the factual factory report with actual time and cost, then export the full BAND room unchanged and record the room demonstration.

Demonstrate the main customer flow and one advanced manager operation. Explain an actual defect the factory caught if one occurred. If no defect occurred, say that. Report hidden-test and untested limitations plainly.

Publish a public GitHub repository only after the genuine run and required files exist. No remote has been created for this preparation checkout.
